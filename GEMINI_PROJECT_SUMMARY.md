# Project Summary: nautilus_trader

This summary was generated by Gemini to provide a quick overview of the project's structure, technology, and purpose.

## 1. Project Overview

*   **Project Name:** `nautilus_trader`
*   **Core Concept:** A high-performance, event-driven algorithmic trading platform designed to unify strategy research, backtesting, and live trading into a single, consistent codebase.
*   **Key Features:**
    *   High-performance core ensuring speed and safety.
    *   Native Python environment for strategy development and data analysis.
    *   Parity between backtesting and live trading environments.
    *   Modular adapter system for connecting to various exchanges and data providers.

## 2. Technical Architecture

This is a hybrid **Rust + Python** project, leveraging Rust for performance-critical components and Python for ease of use and a rich data science ecosystem.

*   **Rust Core (`crates/` directory):**
    *   Organized as a Cargo Workspace with multiple, modular crates.
    *   **Key Crates:** `nautilus-trader-core`, `nautilus-trader-model`, `nautilus-trader-backtest`, `nautilus-trader-live`, and various `adapters`.
    *   **Bridge to Python:** Uses the `PyO3` library to create Python bindings for the Rust core.

*   **Python Layer (`nautilus_trader/` and `python/` directories):**
    *   Uses `Cython` and a `build.py` script to compile the Rust core into a Python extension module.
    *   Provides a high-level API for users to write strategies and interact with the trading engine.
    *   **Key Dependencies:** `numpy`, `pandas`, `pyzmq`, `redis`, `uvloop`.

## 3. Data Flow

1.  **Ingestion:** Data from exchanges enters through Rust-based **adapters**.
2.  **Processing:** The event-driven Rust core processes the data, manages state (order books, positions), and executes logic.
3.  **Interaction:** Python strategies receive market data and send trading instructions to the Rust core via the `PyO3`/`Cython` bridge.
4.  **Communication & State:** A message bus (likely using ZeroMQ/Redis) handles internal communication, and Redis can be used for optional state persistence.
