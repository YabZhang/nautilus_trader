# Nautilus Trader 上手指南

本文档将指导您作为项目新手，如何快速配置环境、构建项目、运行示例，并理解其核心工作原理。

## Part 1: 项目启动手册

我们将以运行一个简单的移动平均线交叉策略（SMA Cross）的回测作为最终目标。

### 第 1 步：环境与工具链准备

1.  **获取项目代码 (您已完成):**
    ```bash
    git clone https://github.com/nautechsystems/nautilus_trader.git
    cd nautilus_trader
    ```

2.  **安装 Rust:**
    项目依赖特定版本的 Rust 工具链。`rust-toolchain.toml` 文件中定义了所需的版本。`rustup` 会在您进入项目目录时自动检测并提示安装。
    *   如果您尚未安装 `rustup`，请访问 [https://rustup.rs/](https://rustup.rs/) 进行安装。
    *   进入项目目录，`rustup` 会自动为您安装正确的 Rust 版本。

3.  **安装 Python:**
    建议使用 Python 3.10 或更高版本。您可以使用 `pyenv` 或其他工具来管理 Python 版本。

4.  **安装 `uv` (推荐):**
    项目使用 `uv` 作为高性能的 Python 包安装和管理工具。
    ```bash
    pip install uv
    ```

### 第 2 步：安装依赖与构建项目

项目提供了一个 `Makefile` 文件，极大地简化了安装和构建流程。

1.  **安装所有依赖 (Rust & Python):**
    ```bash
    make install
    ```

2.  **构建项目:**
    ```bash
    make build
    ```

### 第 3 步：运行回测示例

1.  **下载示例数据:**
    ```bash
    make download-test-data
    ```

2.  **运行回测脚本:**
    ```bash
    python examples/backtest/strategies/sma_cross_strategy.py
    ```
    如果一切顺利，您将在终端看到回测日志，并生成一份 `report.html` 回测报告。

```text
+--------------------------------------------------------------------------+
| 1. SETUP (Python)                                                        |
|    - Script:  examples/backtest/run.py                                    |

                                     |
                                     v
+--------------------------------------------------------------------------+
| 2. DATA LOADING (Rust)                                                   |
|    - Component: Data Engine                                              |
|    - Code:      crates/data/                                             |

+--------------------------------------------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
| 3. EVENT LOOP (Rust Core)                                                |
|    - Component: Backtest Engine + Event Loop                             |
|    - Code:      crates/backtest/ & crates/core/                          |
|    - Flow:      回测引擎驱动事件循环, 将行情数据(Tick/Bar)推入循环     |
+--------------------------------------------------------------------------+
                                     |
                (分发 on_tick/on_bar 事件) |
                                     v
+--------------------------------------------------------------------------+
| 4. STRATEGY LOGIC (Python)                                               |
|    - Component: Your Strategy                                            |
|    - Code:      examples/backtest/strategies/sma_cross_strategy.py       |

+--------------------------------------------------------------------------+
                                     |
                         (提交 Order) |
                                     v
+--------------------------------------------------------------------------+
| 5. ORDER EXECUTION (Rust)                                                |
|    - Component: Execution Engine                                         |
|    - Code:      crates/execution/                                        |
|    - Flow:      接收 Order, 模拟撮合, 生成成交回执 (Fill)                |
+--------------------------------------------------------------------------+
                                     |

+--------------------------------------------------------------------------+
| 6. STATE MANAGEMENT (Rust)                                               |
|    - Component: Portfolio Engine                                         |
|    - Code:      crates/portfolio/                                        |

+--------------------------------------------------------------------------+
                                     |

+--------------------------------------------------------------------------+
| 7. OUTPUT                                                                |
|    - Action:  回测结束, 生成日志和 report.html                            |
```

### 关键模块代码定位 (相对路径)

*   **核心数据模型 (Rust):** `crates/model/src/`
    *   *定义了如 `Instrument`, `Order`, `Fill`, `Tick`, `Bar` 等所有核心数据结构。*
*   **数据引擎 (Rust):** `crates/data/src/`
    *   *负责数据的解析、加载和流式处理。*
*   **回测引擎 (Rust):** `crates/backtest/src/`
    *   *回测的主要逻辑，负责驱动事件循环和模拟交易。*
*   **核心事件处理 (Rust):** `crates/core/src/`
    *   *包含事件总线和最核心的事件循环机制。*
*   **执行与撮合 (Rust):** `crates/execution/src/`
    *   *模拟订单在交易所的执行过程。*
*   **账户与组合 (Rust):** `crates/portfolio/src/`
    *   *管理仓位、资金、计算盈亏等。*
*   **示例策略 (Python):** `examples/backtest/strategies/`
    *   *存放各种策略实现，是学习和开发策略的起点。*

## Part 3: 核心模块深度解析

本部分将深入探讨 `nautilus_trader` 的核心模块，解释它们的设计理念和工作流程。

### 1. 核心数据模型 (Core Data Models)

这是整个系统的基石，无论是回测还是实盘，都在使用同一套数据结构，定义在 `crates/model/` 模块中。

- **`Instrument` (金融工具):** 描述一个可交易的金融产品，包含ID、交易所、交易对、精度、合约类型等。
- **`Tick` 和 `Bar` (市场数据):** `Tick` 是最细粒度的价格跳动，`Bar` 是聚合后我们熟知的K线。
- **`Order` (订单):** 代表向市场发出的交易意图，包含方向、价格、数量、订单类型、状态等。
- **`Position` (仓位):** 表示在某个工具上持有的净头寸，包含数量、平均开仓价、未实现盈亏等。
- **`Fill` (成交):** 表示一笔订单的部分或全部成交，是触发账户状态变化的最重要事件。

### 2. 数据引擎 (Data Engine)

数据引擎是系统的“供血系统”，负责将不同来源的数据（文件、网络流等）转化为统一、有序的事件流。

```text
+--------------------------------------------------------------------------+
| 1. 数据源 (Data Source)                                                  |
|    - 目标: 原始数据文件, 例如 `BTC-USDT.csv`                             |
+--------------------------------------------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
| 2. 读取器 (Reader/Provider)                                              |
|    - 职责:     从物理介质读取原始数据块。                                |
+--------------------------------------------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
| 3. 解析器 (Parser)                                                       |
|    - 职责:     将原始数据块翻译成系统可识别的 `Tick` 或 `Bar` 对象。     |
+--------------------------------------------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
| 4. 数据流 (Data Stream) - **引擎核心**                                   |
|    - 职责:     协调者，对外提供统一的、按时间排序的事件迭代器。         |
+--------------------------------------------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
| 5. 消费者 (Consumer)                                                     |
|    - 角色:     回测引擎或实盘引擎                                        |
|    - 动作:     不断调用 `next()` 获取下一个市场事件。                    |
+--------------------------------------------------------------------------+
```

- **核心概念:** **管道 (Pipeline)** 和 **迭代器 (Iterator)**。数据像在管道中一样被处理，而整个引擎对外表现为一个简单的迭代器，实现了高度解耦和内存效率。

### 3. 事件处理流程 (Event Handling Flow)

这是系统的核心脉络，使各个独立的模块能够通过 **广播和监听事件** 来协作，而非直接调用。

```text
Event: Market Tick arrives
   |
   v
[Backtest Engine's Event Loop]
   |
   '-> Routes Tick to -> [Python Strategy's `on_tick` handler]
                            |
                            '-> Generates `Order` command
                            |
                            v
[Backtest Engine's Event Loop]
   |
   '-> Routes Order to -> [Execution Engine]
                            |
                            '-> Simulates trade, generates `Fill` Event
                            |
                            v
[Backtest Engine's Event Loop]
   |
   '-> Routes Fill to -> [Portfolio Engine]
   |                      |
   |                      '-> Updates position/PnL
   |
   '-> (Also) Routes Fill to -> [Python Strategy's `on_fill` handler]
```

- **核心概念:** **事件驱动 (Event-Driven)**。系统由事件的产生和消费驱动，高度解耦，可扩展性强，并能真实地模拟现实世界交易的异步性。

### 4. 回测引擎 (Backtest Engine)

回测引擎是整个系统的“总指挥”，负责驱动整个模拟过程，连接数据、策略、执行和状态。

- **核心概念:** **时间主导 (Time-Driven)** 和 **责任分离 (Separation of Concerns)**。引擎严格按时间顺序处理事件，保证了回测的有效性。它本身不负责具体业务逻辑，而是将任务分发给专职模块（如执行引擎、组合模块）。

### 5. 执行引擎与撮合成交 (Execution Engine & Matching)

执行引擎在回测中扮演 **“虚拟交易所”** 的角色，根据一套严格的规则，模拟订单的成交过程。

```text
+--------------------------------------------------------------------------+
| 1. 接收指令 (Receive `Order`)                                            |
+--------------------------------------------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
| 2. 应用撮合逻辑 (Apply Matching Logic)                                   |
|    - 市价单 (Market): 按当前的买一/卖一价立即成交。                      |
|    - 限价单 (Limit): 仅当市场价优于或等于限价时成交。                    |
|    - 止损单 (Stop): 市场价达到触发价后，激活为市价单或限价单。           |
+--------------------------------------------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
| 3. 生成结果 (Generate `Fill` or other status events)                     |
+--------------------------------------------------------------------------+
```

- **核心概念:** **基于`Tick`的模拟**。由于回测中没有真实的订单簿，撮合逻辑使用当前的 `Tick` 数据（买一价/卖一价/最新价）作为判断基准，并可配置滑点和手续费模型以提高真实性。

### 6. 投资组合与账户模块 (Portfolio & Account)

这是系统的 **“财务总管”** 或 **“记账本”**，被动地记录所有交易活动对账户状态的影响。

```text
+--------------------------------------------------------------------------+
| 1. 接收收据 (Receive `Fill` Event)                                       |
+--------------------------------------------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
| 2. 更新账户现金 (Update Account Balance)                                 |
|    - 扣除交易成本和手续费。                                              |
+--------------------------------------------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
| 3. 更新资产持仓 (Update Positions)                                       |
|    - 增加或减少资产持有数量，重新计算平均开仓价。                        |
+--------------------------------------------------------------------------+
                                     |
                                     v
+--------------------------------------------------------------------------+
| 4. 计算并区分盈亏 (Calculate PnL)                                        |
|    - 平仓时: 计算 **已实现盈亏 (Realized PnL)**，计入现金余额。          |
|    - 持仓时: 计算 **未实现盈亏 (Unrealized PnL)**，影响账户净值。        |
+--------------------------------------------------------------------------+
```

- **核心概念:** **状态记录**。此模块是系统状态的最终记录中心，精确地区分 **账户余额 (Balance)** 和 **账户净值 (Equity)**，以及 **已实现盈K (Realized PnL)** 和 **未实现盈亏 (Unrealized PnL)**。
